# WeekPlanner

Рабочий прототип недельного планировщика: React + TypeScript + Vite, Supabase Auth/Postgres/Realtime, PWA. Один веб-клиент для macOS, Windows и браузера. Папка проекта на этом компьютере: `C:\Users\Sergey\Documents\WeekPlanner`.

## Запуск без командной строки на Windows

На рабочем столе создан ярлык **WeekPlanner**. Дважды щёлкните по нему: сервер запустится в фоне, а планировщик откроется в браузере по прежнему адресу `http://127.0.0.1:5173/`. Если сервер уже работает, повторный запуск просто откроет приложение. Данные деморежима сохраняются для этого адреса; используйте тот же браузер и профиль.

Также можно открыть файл `WeekPlanner.vbs` в папке проекта. `start-app.ps1` запускает Vite без видимого окна и ждёт готовности сервера; журналы находятся в `work/launcher/`. При ошибке появляется обычное окно с сообщением. Закрытие браузера не останавливает фоновый сервер; после перезагрузки компьютера ярлык запустит его заново. Автозапуск при входе в Windows не добавлялся.

## Быстрый запуск

Нужен Node.js 22.12+ (проверено на Node.js 24) и npm.

```sh
cd ~/Documents/WeekPlanner
npm install
npm run dev
```

Windows PowerShell:

```powershell
cd "$HOME\Documents\WeekPlanner"
npm.cmd install
npm.cmd run dev
```

Открыть **http://127.0.0.1:5173/**. Если PowerShell блокирует `npm.ps1`, используйте `npm.cmd`. Сервер использует фиксированный порт 5173; если он занят, закройте предыдущий сервер или задайте другой порт и внесите его в Supabase Redirect URLs.

Без переменных Supabase приложение запускается с 13 примерами на текущую неделю и хранит демозадачи в localStorage. Это временный слой разработки, **он не синхронизируется между устройствами**. После добавления обеих переменных автоматически используется Supabase; облачные ошибки не переключают приложение в деморежим. Частично заполненная конфигурация показывает ошибку. Демоданные и облачные задачи разделены, автоматического импорта демозадач нет.

## Что работает

- Сетка понедельник–воскресенье, временная шкала, текущая дата, индикатор текущего времени, мини-календарь, переходы между неделями, «Сегодня».
- Создание кнопкой «Задача», клавишей N, плюсом в заголовке дня или нажатием на час в сетке. Новая задача сразу сохраняется с временным названием.
- Редактор: название, описание, дата, начало/окончание, категория, индивидуальный цвет, приоритет, выполненность, заметки. Длительность меняется через время окончания.
- Автосохранение через 650 мс после последней правки. Закрытие панели дожидается сохранения. Неверное время блокирует сохранение с понятным сообщением; ошибочную правку можно исправить или явно отбросить.
- Перенос между днями за ручку ⋮⋮ с сохранением времени и длительности. Поддерживаются мышь, pointer/touch и клавиатура: фокус на ручке, пробел, стрелки, пробел; Escape отменяет перенос. Дату всегда можно изменить в редакторе.
- Удаление с подтверждением, выполнение на карточке или в редакторе.
- Поиск в названии, описании и заметках; фильтры категории, статуса и высокого приоритета. Статистика показывает всю неделю, независимо от фильтров.
- Восемь категорий. Цветной квадратик в боковой панели меняет цвет категории для новых задач; существующие задачи сохраняют свой индивидуальный цвет. Выбор категории в редакторе подставляет её актуальный цвет.
- Светлая/тёмная тема, запоминание выбора, горизонтальная прокрутка сетки на узких экранах.
- Supabase service layer: вход через Google и по email, CRUD, Realtime, повторная загрузка при восстановлении сети и возвращении к вкладке.
- AI Assistant: реальные локальные запросы «Что у меня завтра?» и поиск свободных двухчасовых интервалов. Свободный текст пока не выполняет команды.
- Отдельная кнопка диктовки. Web Speech API включается только при наличии поддержки, с русским языком и обработкой ошибок/отказа в доступе. Диктовка может использовать серверную службу браузера. Платные AI API не подключены.
- PWA manifest, PNG-иконки, service worker, локальные шрифты и offline-кэш оболочки production-сборки.

## Вставка расписания из нашего разговора

Обсудите со мной задачи, свободные часы и приоритеты, затем попросите: **«Выдай готовый блок расписания для вставки в WeekPlanner»**. Я подготовлю текст с днями, временем и категориями.

Откройте планировщик через ярлык, нажмите **«Вставить расписание» → «Проверить расписание» → «Добавить в план»**. Этот же импорт доступен в панели AI Assistant. Если текст уже введён в панели помощника, он переносится в импорт.

Пример (дата после «Неделя» — понедельник):

```text
Неделя: 2026-09-14

Понедельник
10:00–13:00 | Работа над MAX450 | 3D / CGI
15:00–15:40 | Английский | Английский

Четверг
15:00–16:00 | Созвон с клиентом | Заказы | Приоритет: высокий
```

Вместо дня недели можно указать точную дату `2026-09-14` или `14.09.2026`. Если строки «Неделя» нет, используются дни недели, выбранной в панели импорта. Категория необязательна — по умолчанию «Другое». Дополнительные поля через `|`: `Описание: …`, `Заметки: …`, `Приоритет: высокий/обычный/низкий`. Символ `|` отделяет поля, поэтому не используйте его внутри названия или заметок.

План сначала показывается без записи в базу. Нераспознанные строки, неизвестные категории, неверные даты и время блокируют добавление всего блока и показывают номер строки. Пересечения по времени требуют явной отметки в просмотре. Повторы по названию, дате и временному интервалу пропускаются. Добавление до 200 задач выполняется одним вызовом data layer; Supabase делает один атомарный запрос с устойчивыми UUID для безопасного повтора после потери ответа. Изменять SQL-схему не требуется.

Это перенос **готового согласованного расписания**: свободное обсуждение, выбор времени и распределение нагрузки происходят в нашем чате. Приложение пока не понимает произвольные фразы вроде «разгрузи пятницу». Импорт создаёт задачи и не заменяет существующее расписание. Без Supabase они сохраняются в деморежиме; после подключения — в облаке.

Код: `src/features/schedule-import/` (разбор текста, проверка повторов/пересечений, панель просмотра), `src/services/scheduleImport.ts` (массовое действие), метод `createMany` обоих repository. Тесты: `parseSchedule.test.ts`, `scheduleImport.test.ts`, `tests/e2e/schedule-import.spec.ts`.

## Подключение Supabase

1. Создайте проект Supabase.
2. В **SQL Editor** выполните файл `supabase/schema.sql` целиком. Это начальная миграция для нового проекта, выполняется **один раз** внутри транзакции.
3. В **Authentication → Providers** включите Email. Для входа по почте используется magic link: Supabase создаёт аккаунт при первом входе. Для Google выполните [отдельную инструкцию](docs/google-login.md).
4. В **Authentication → URL Configuration** задайте Site URL и добавьте Redirect URLs: `http://127.0.0.1:5173`, при необходимости `http://localhost:5173`, `http://127.0.0.1:4173` для production preview, позднее ваш HTTPS-домен. Письмо нужно открыть в браузере на том устройстве, на котором вы входите.
5. Скопируйте Project URL и **anon / publishable key** из настроек проекта. Создайте рядом с `package.json` файл `.env.local` на основе `.env.example`:

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

6. Перезапустите dev-сервер. Для production пересоберите приложение — Vite встраивает эти переменные во время сборки.
7. Нажмите «Войти для синхронизации» и выберите Google или ссылку по email. Войдите с **одним email** на Mac и Windows. Используйте один и тот же Supabase-проект.

SQL создаёт `tasks`, `categories`, индексы, `created_at`/`updated_at`, триггер категорий для новых пользователей, начальные категории для уже существующих пользователей и RLS-политики. Пользователь видит и меняет только свои строки. Составной внешний ключ не позволяет назначить задаче категорию другого пользователя. Таблицы добавляются в публикацию `supabase_realtime`.

В браузере допустим **только публичный anon/publishable key**, никогда `service_role`, secret key или ключ LLM. `.env`, `.env.local` и другие `.env.*` исключены из Git; `.env.example` содержит только пустые значения. RLS обеспечивает защиту данных, публичный ключ не является секретом.

### Проверка облака после настройки

1. Откройте два разных браузера/устройства под одним аккаунтом. Дождитесь статуса «Синхронизировано».
2. Создайте задачу в первом, проверьте появление во втором. Измените время, дату, выполненность; затем удалите задачу и проверьте оба экрана.
3. В отдельном профиле войдите под другим email: задачи первого пользователя должны быть недоступны.
4. Отключите интернет на одном устройстве, измените задачу на другом, восстановите подключение — список должен обновиться.
5. Если Realtime недоступен, проверьте публикацию таблиц и настройки проекта. Ошибка отображается в интерфейсе, повторное открытие вкладки загружает актуальный список.

**Без вашего проекта и ключей реальная синхронизация между устройствами и SQL на Supabase в этой сессии не проверены.** Подготовлены клиент, SQL и шаги проверки.

Официальные справочники: [RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes), [Vite PWA](https://vite-pwa-org.netlify.app/guide/).

## Offline и PWA

```sh
npm run build
npm run preview -- --host 127.0.0.1 --port 4173
```

Откройте **http://127.0.0.1:4173/** онлайн хотя бы один раз. После активации service worker оболочка запускается без сети. В деморежиме можно менять задачи offline. В облачном режиме доступен просмотр последнего кэша **текущего авторизованного пользователя**; запись без сети пока блокируется явно. Очередь offline-изменений с повторной отправкой — следующий этап. При выходе из аккаунта его локальный кэш удаляется. Не очищайте данные браузера, если нужны демозадачи.

Service worker отключён в dev-режиме; проверяйте offline/установку на production preview. Обновление приложения активируется после закрытия старых вкладок, без внезапного перезапуска редактора. Ответы Supabase Auth/API не кэшируются service worker.

Для установки используйте кнопку установки в адресной строке Chrome/Edge на Windows или macOS. Доступность системного пункта зависит от браузера. На общем HTTPS-домене PWA можно открыть и установить на обоих устройствах. `localhost`/`127.0.0.1` относится к конкретному компьютеру: запуск здесь не публикует приложение для Mac. Разместите папку `dist` на HTTPS static hosting с SPA fallback на `index.html` и добавьте домен в Supabase Redirect URLs. Хостинг в первом этапе не настраивался.

UI → `PlannerActions` → `PlannerRepository` → Supabase или демохранилище. Компоненты не вызывают таблицы напрямую. Провайдер управляет загрузкой, сериализацией записей и подписками. Даты/время задач — календарные значения без UTC-преобразования: 10:00 остаётся 10:00 при просмотре на другом устройстве. `created_at`/`updated_at` — UTC timestamps. Планировщик ориентирован на одну личную часовую зону; преобразование расписания при путешествиях пока не реализовано.

Действия будущего AI:

```text
createTask(input)                 → сохранённая задача
updateTask(id, patch)             → сохранённая задача
deleteTask(id)                    → удаление
moveTask(id, date, startTime?)     → перенос с сохранением длительности
findFreeSlots(date, minutes, ...) → свободные интервалы не короче minutes
getDaySchedule(date)              → расписание дня
getWeekSchedule(monday)           → расписание недели
rescheduleDay(date, shiftMinutes) → предложение изменений
rescheduleWeek(monday, shiftDays) → предложение изменений
```

Последние два действия возвращают **предложение**, не меняют БД. Это простой сдвиг незавершённых задач, не оптимизатор конфликтов. Перед применением массовых AI-изменений будущий интерфейс должен показать план. Для атомарного применения понадобится SQL RPC/транзакция. `AssistantAdapter` принимает текст и ограниченный контекст чтения, возвращает типизированное предложение; LLM можно заменить независимо от UI. Подключать OpenAI/другую LLM следует через сервер/Edge Function, где хранится секретный ключ.

Под повторения зарезервированы тип `RecurrenceRule`, поля `recurrence` и `series_id`. Генерация серий, исключения и редактирование «это событие / вся серия» **пока не реализованы**. В первом этапе не реализованы растягивание карточки мышью, offline-очередь, push-уведомления и Tauri. Время/длительность уже меняются в редакторе. Ночные задачи пока разделяются на два дня.

Одновременные правки разных полей применяются как PATCH. При изменении одного поля на двух устройствах действует последнее принятое сервером значение. Расширенное разрешение конфликтов и версии записей — следующий этап. В первом прототипе загружаются задачи пользователя одним запросом (учитывайте лимит строк Supabase); далее нужен диапазон дат/пагинация для больших архивов.

### Graphify для карты проекта

Graphify подключён как локальный инструмент разработки. Готовая карта WeekPlanner находится в `graphify-out/` и не попадает в Git. Чтобы зарегистрировать навык глобально для всех проектов Codex без командной строки, дважды щёлкните `Install Graphify.vbs`, дождитесь сообщения об успешной установке и один раз перезапустите Codex. Скрипт ставит официальную версию `graphifyy` в `%USERPROFILE%\.codex\tools\graphify` и копирует навык в `%USERPROFILE%\.codex\skills\graphify`.

Файл `.graphifyignore` исключает `node_modules`, сборку, временные файлы и все `.env`/локальные конфигурации. Карта строится локальным AST-анализатором; исходный код никуда не отправляется.

```sh
npm run typecheck
npm run build
npm run lint
npm test
npm run test:e2e
npm run test:auth
npm run format:check
```

Для E2E нужен установленный Google Chrome (channel `chrome` в `playwright.config.ts`). Тесты используют изолированные профили и не меняют ваши данные. При другом окружении поменяйте channel или установите Chromium Playwright. E2E проверяют CRUD, автосохранение при быстром закрытии и после перезагрузки, изменение времени, выполнение, drag-and-drop, поиск, недели, темы, помощника, узкий экран и некорректный ввод. Юнит-тесты проверяют даты, перенос с длительностью, поиск свободного времени, предложения переноса и перекрывающиеся карточки.

`npm run test:auth` проверяет вход в отдельном тестовом сервере на порту 5183 с подменёнными ответами Supabase, без реальных аккаунтов и ключей. Для проверки пути GitHub Pages в PowerShell задайте `$env:WP_AUTH_BASE_PATH='/WeekPlanner/'` перед запуском. Настройка настоящего входа описана в [docs/google-login.md](docs/google-login.md).

Git инициализирован, ветка `main`, remote — `seregagansta/WeekPlanner`. Для переноса проекта на второй компьютер используйте этот репозиторий; локальную `.env.local` настройте отдельно. Не коммитьте настоящие ключи.

Первый коммит не создан: среда Windows/Codex отклоняет создание `.git/index.lock` даже после выдачи доступа. Сам проект и Git-репозиторий созданы. Для сохранения первого коммита выполните в своём терминале:
